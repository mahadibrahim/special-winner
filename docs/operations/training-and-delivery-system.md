# Training & Delivery System — canonical map

**If you're looking for "the training decks," "the coach/ref/venue-manager SOPs," "how we onboard staff," or "the safety standards" — everything is indexed here.** This is the single source of truth for how Aspire trains and equips the people who deliver classes, clinics, camps, and league days.

Last major build: 2026-07. Everything below is content-as-code — edit the source, regenerate, commit; CI keeps the generated artifacts in sync.

---

## 1. Role training decks (the presentations)

Nine self-contained, branded HTML slide decks — one per operational role — that open in a browser and print to PDF. Each teaches: **why the role matters** (purpose + company philosophy), **the procedures** (SOPs with tools and day-of timing), and **how to use the software** (a "Using the system" chapter with real app screenshots).

| What | Where |
|---|---|
| The decks (open these) | `docs/operations/artifacts/training/role.<id>.deck.html` — coach, ref, venue_manager, event_lead, front_of_house, facilities, director, photographer, team_captain |
| Deck generator (source) | `src/lib/ops-catalog/views/training-deck.ts` |
| Regenerate | `npm run catalog:render` (also renders manuals). CI (`ops-catalog` workflow) rejects PRs where the rendered decks are out of sync with the catalog. |
| Committed screenshots the decks embed | `training/screenshots/<role>/**` (activity slots + `tour/` for the "Using the system" chapter) |

Decks regenerate automatically from the catalog + screenshots, so they can't silently drift from the operating model.

## 2. Role manuals (the written SOPs)

The long-form, hand-and-generated procedures behind the decks.

| What | Where |
|---|---|
| Per-role manuals | `docs/operations/artifacts/manuals/role.<id>.md` (generated; `role.coach.md` is hand-authored) |
| SOP source of truth | `docs/operations/catalog/activities/*.yaml` — one activity per file; the `sop_body` field is the procedure |
| Roles / features / artifacts | `docs/operations/catalog/{roles,features,artifacts}/` |
| Schema + how to edit | `docs/operations/README.md` and `docs/superpowers/specs/2026-05-06-game-day-operating-model-design.md` |

All 63 activities have authored procedures reflecting the owner's operating model (see §5).

## 3. Walkthrough videos & narration (the how-to-use-the-software media)

A separate, on-demand pipeline that drives the real app and records it. **Not run in CI** — regenerated by command against a seeded dev server.

| What | Where / command |
|---|---|
| Videos + captions | `npm run training:videos` → `training/output/<workflow>/` (gitignored) |
| Narration scripts | `npm run training:narration` → `training/narration/<workflow>.md` (committed) |
| Walkthrough specs | `training/walkthroughs/*.walkthrough.ts` |
| Pipeline docs | `training/README.md` |

TTS-voiced video is designed but unbuilt (needs a `TRAINING_TTS_API_KEY`).

## 4. Safety & policy standards (the research grounding the SOPs)

Cited standards a rec operator can adopt — the numbers the SOPs reference instead of guesses.

- `docs/operations/reference/safety-and-policy-standards.md` — WBGT heat thresholds, NWS 30-30 lightning, CPSC/ASTM goal anchoring, **Ohio youth-concussion law (ORC 3707.511 — a legal obligation)**, SafeSport/abuse-prevention, weather refund/credit norms. Flagged: concussion & abuse items need counsel sign-off before treating as final policy.

## 5. The operating model (the owner's decisions the SOPs encode)

The business decisions that drive the SOP content — cashless, escalation chain, pay/payroll, refund/credit, media consent. These are recorded in the assistant's project memory (`operating-model-decisions`) and reflected across the catalog SOPs. Key points: cashless everywhere; escalation Coach → Venue Manager → Director; refs per-match (locked on in-app closeout), coaches/venue-managers hourly; Gusto weekly; no weather refunds → reschedule → credit; media adults opt-out / kids stricter-but-workable.

## 6. Coach lifecycle (the shipped product features behind delivery)

The live product surfaces that operationalize delivery — hire → onboard → sequenced plans → assessment.

- Program plan: `docs/superpowers/plans/2026-07-06-coach-lifecycle-and-delivery-ops.md`
- Shipped: coach compliance/credentials + hire→account handoff, onboarding checklist, season-level session-plan sequencing, assessment cadence. (See git history / that plan's phases.)

## 7. Product backlog (what's still to build)

Builds the SOP review surfaced but that need software, not just procedure.

- `docs/product/backlog-from-sop-review-2026-07.md` — account-credit balance, ejection/suspension tracker, in-app incident reporting, in-app time-tracking + geofencing, Gusto-format export, media do-not-publish shortlist. Owner-agreed priority is recorded in that doc's "Sequencing" section.

## Regenerate everything (quick reference)

```bash
npm run catalog:validate     # check the SOP catalog is well-formed
npm run catalog:render       # regenerate manuals + decks (commit the output)
npm run training:videos      # re-record walkthrough videos (dev server up, seeded)
npm run training:narration   # regenerate narration scripts from captions
```
