# Person 360 — Make Every Action Live (fast-follow) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the Person 360 card + command-center stubs into fully functional features — real `today` sessions + check-in, live send-link, real photo upload, a true outstanding balance, a +Walk-in session picker, Find-booking, and the full-profile page.

**Architecture:** Extends the merged `GET /api/admin/person/[id]` payload (`build-person-profile.ts`) and `PersonCard`/`CommandSearchBar`. Reuses the existing roster/check-in queries (`api/admin/check-in/event.ts`), the photo-upload infra (`lib/.../photo-upload.ts`), the kiosk booking search, and `WalkInFlow` + `VenueTodayPayload`. New: a person-photo endpoint, an admin booking-search endpoint, a session-picker, a find-booking panel, and a `/admin/people/[id]` page.

**Tech Stack:** Astro 5 + React 19, Drizzle (PostgreSQL), Zod, Tailwind, Vitest (unit + api), Playwright (e2e).

## Global Constraints

- **Scope:** make the Person 360 + command-center actions live. No new product surfaces beyond what's listed here.
- **Tenant scoping:** every new read/write is admin-gated + org/location-scoped via the existing helpers (mirror `lib/person/build-person-profile.ts`'s `isUserInOrg` gate and `lookup.ts`). Never leak/mutate cross-org.
- **Reuse, don't rebuild:** roster/booking queries from `src/pages/api/admin/check-in/event.ts`; photo write via `src/lib/.../photo-upload.ts` (`{kind:"user"|"family_member", id}`); booking search from the kiosk `search.ts`; `WalkInFlow` + `VenueTodaySession`/`VenueTodayPayload`; `SendLinkActions`, `AvatarUploader`, `StatusChip`, `Sheet`.
- **Check-in reality:** `/api/admin/check-in/check-in` accepts ONLY `drop_in_booking | field_rental`. Game `roster_entry` attendance is NOT tracked in v1 — for roster today-items, show status but DISABLE check-in (no fake button).
- **Money is integer cents.** UI primitives: `ErrorBanner`/`LoadingSkeleton`/`EmptyState`; toasts via sonner.
- **TDD** for pure logic + endpoints. Components have NO unit tests (Testing Library not installed) — covered by e2e. Ignore the pre-existing `tests/unit/soccerone/venues.test.ts` DATABASE_URL failure. The person endpoint is slow against staging — give data-dependent e2e assertions realistic timeouts (`test.setTimeout(90_000)`, 60s waits).

### Task 2: True outstanding balance

**Files:**
- Create: `src/lib/person/compute-outstanding.ts`
- Test: `tests/unit/compute-outstanding.test.ts`

**Interfaces:**
- Produces: `computeOutstandingCents(regs: { paymentStatus: string; amountDueCents: number; amountPaidCents: number }[]): number` — sums `max(0, amountDueCents - amountPaidCents)` for rows with `paymentStatus` in `{"unpaid","deposit_paid"}`; 0 for paid/refunded.

- [ ] **Step 1:** Failing test `tests/unit/compute-outstanding.test.ts`:
```ts
import { describe, it, expect } from "vitest";
import { computeOutstandingCents } from "@/lib/person/compute-outstanding";
describe("computeOutstandingCents", () => {
  it("sums unpaid + deposit_paid shortfalls, ignores paid/refunded", () => {
    expect(computeOutstandingCents([
      { paymentStatus: "unpaid", amountDueCents: 10000, amountPaidCents: 0 },
      { paymentStatus: "deposit_paid", amountDueCents: 10000, amountPaidCents: 4000 },
      { paymentStatus: "paid", amountDueCents: 5000, amountPaidCents: 5000 },
      { paymentStatus: "refunded", amountDueCents: 5000, amountPaidCents: 0 },
    ])).toBe(16000);
  });
  it("never goes negative", () => {
    expect(computeOutstandingCents([{ paymentStatus: "unpaid", amountDueCents: 1000, amountPaidCents: 5000 }])).toBe(0);
  });
});
```
- [ ] **Step 2:** Run it, watch it fail: `npx vitest run --config vitest.config.ts --project unit tests/unit/compute-outstanding.test.ts`.
- [ ] **Step 3:** Implement `compute-outstanding.ts`:
```ts
const OWES = new Set(["unpaid", "deposit_paid"]);
export function computeOutstandingCents(
  regs: { paymentStatus: string; amountDueCents: number; amountPaidCents: number }[],
): number {
  return regs.reduce(
    (sum, r) => sum + (OWES.has(r.paymentStatus) ? Math.max(0, r.amountDueCents - r.amountPaidCents) : 0),
    0,
  );
}
```
- [ ] **Step 4:** Run it, watch it pass.
- [ ] **Step 5:** In `buildPersonProfile`, set `payments.outstandingCents = computeOutstandingCents(<the registration rows it already loads, which carry paymentStatus/amountDueCents/amountPaidCents>)`, set the `outstanding_balance` flag from it, and remove the v1-limitation caveat comment. (The registration rows are already queried for the registrations list — reuse them; add the two amount columns to that select if missing.)
- [ ] **Step 6:** `npx tsc --noEmit` (0); `npm run test:unit` (no regressions). Commit `feat(person): real outstanding balance from registrations`.
